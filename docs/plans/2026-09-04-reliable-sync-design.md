# 可靠同步与本地修正设计

## 目标与边界

纸间课表已经能够从北信科“当前课表”识别完整学期并在确认后保存。本次升级把一次性的“导入并替换”改造成可比较、可恢复、允许本地修正的同步流程。用户在确认前能看到新增、修改和移除数量；确认后可撤销最近一次同步。手动课程、对教务课程的长期修正以及按日期设置的临时停课或调课都保存在本机，后续同步不得覆盖。

本次不修改 BISTU WebView 域名白名单、登录方式、页面提取脚本或教务接口。应用仍不读取和保存账号、密码、验证码或 Cookie 文本，也不增加服务器和云同步。

## 方案比较

| 方案 | 优点 | 代价 | 结论 |
| --- | --- | --- | --- |
| 来源感知的基线课表 + 本地覆盖层 + 单份快照 | 同步规则容易解释；手动内容天然保留；可撤销；适合现有 Room 架构 | 需要一次数据库迁移和覆盖层合成逻辑 | 采用 |
| 对每个字段做三方合并 | 能细粒度合并教务变化和本地修改 | 冲突界面复杂，用户难以判断哪一项生效 | 暂不采用 |
| 记录每次编辑的完整事件流 | 历史最完整，可回放任意版本 | 对单机 MVP 过重，查询和迁移成本高 | 不采用 |

## 数据模型

课表数据分为四层：

1. `IMPORTED` 基线：最近一次从教务系统确认同步的课程和上课安排。
2. `MANUAL` 课程：用户自行新增的完整学期安排，同步只替换 `IMPORTED`，不触碰该层。
3. `schedule_overrides`：以稳定的教务安排键为目标，保存“长期替换”或“隐藏”操作。编辑教务课程写入替换覆盖；删除教务课程写入隐藏覆盖；用户可恢复教务版本。
4. `schedule_exceptions`：以安排键和原上课日期为目标，保存单次停课或调课。调课包含新日期、节次和可选教室，允许跨教学周移动。

每个教务安排的稳定键由学期、课程、教师、星期、起止节次以及同槽位序号生成，不包含教室和周次，因此常见的教室或周次变化仍能识别为“修改”。数据库从版本 1 升至版本 2；旧课程默认标记为 `IMPORTED`，旧安排以原主键作为初始稳定键。同步前将当前教务基线编码到 `import_snapshots`，每学期只保留最近一份。

## 同步与显示数据流

解析器得到 `ImportedSchedule` 后，仓库读取同学期的教务基线并计算差异。完全相同的安排无须写库；有变化时，预览显示新增、修改、移除数量和少量示例。用户确认后，Room 事务依次保存旧基线快照、更新学期元数据、删除旧 `IMPORTED` 课程并插入新基线。现有学期已经人工校准过的第一周日期继续保留。

课表展示先把教务基线、手动课程和长期覆盖合成为“有效学期课表”，再按所浏览教学周应用日期例外：原日期命中停课或调课时隐藏原安排；调课的新日期落在当前周时生成一次性的显示安排。今日摘要和周网格消费同一套合成结果，避免两种视图不一致。

撤销读取最近快照并只恢复教务基线，手动课程、长期覆盖和日期例外保持不变。撤销成功后删除该快照，防止连续点击在两个版本间来回切换造成困惑。

## 编辑、错误处理与验证

“课表设置”增加“管理课程”和“撤销上次同步”。管理页列出教务、手动和已修正安排，支持新增、编辑、删除、恢复教务版本，并集中展示临时调整。表单校验课程名、星期、节次和周次；临时调整还校验原日期确实是该课程的上课日，且新日期位于当前学期范围内。任何校验或数据库错误都保留当前界面和原数据，只显示可理解的错误。

纯 Kotlin 测试覆盖差异分类、覆盖层优先级、停课、同周及跨周调课。数据库构建开启 Room schema 导出并注册 `MIGRATION_1_2`。最终运行全部 JVM 测试、Android Lint 和 Debug APK 构建；由于自动化构建不能证明真实登录和设备视觉效果，仍需在真机上完成一次“识别—查看差异—同步—手动修正—再次同步—撤销”的完整验收。
